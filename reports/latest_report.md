# 주행 실행시간 최적화 벤치마크 결과 (B0 → V1 → V2 → V3) — 2026-11-14 v01

승인된 벤치마크 6회 중 **5회를 실행했고, V3b에서 판정 불합격이 나와 규칙대로 멈췄습니다.** 마지막 단계인 HR 무검출 시험(V3F)은 실행하지 않았습니다. 모든 실행은 기술 시험(counted=false)입니다. 기존 코드와 기존 성공 기록은 바꾸지 않았습니다. 본실험, Controller v04 승인 파일, 렌더, 재학습은 그대로 둡니다.

## 결론

- **V3a 실측: 1회 305초.** 기준 420초보다 27% 빨라졌고, 궤적·명령·최종 오차·안전 판정은 B0와 같습니다.
- **목표 240초 이하는 달성하지 못했습니다.** 남은 시간은 대부분 PhysX 계산, 렌더, 실시간 속도 제한(초당 60스텝)이 차지하며, 안전 기준을 그대로 두고는 줄이기 어렵습니다.
- **V3b가 주행 시작 직후 `CONTROLLER_READBACK_MISSING`으로 안전 정지했습니다.**
  - 원인: 시뮬레이션이 빨라지면서, 기존 안전검사가 허용하는 시간(시뮬레이션 0.1초)이 실제 시간으로는 약 260 ms에서 약 90–170 ms로 줄었습니다. 그 사이 ROS 첫 명령의 전달 지연이 이 범위를 넘었습니다.
  - 로버는 움직이지 않았고 충돌도 없습니다. 하지만 이 문제를 해결하기 전에는 **V3를 본실험에 적용할 수 없습니다.**
- **540회 예상:**
  - 1회 305초, 주행 전 실패 약 50초, 실행 사이 2초를 기준으로 계산했습니다.
  - 주행까지 가는 비율이 50%면 26.9시간, 70%면 34.6시간, 100%면 46.1시간입니다.
  - **36시간 안에 끝나려면 주행 비율이 약 74% 이하여야 합니다.**

**사전 오프라인 검증 (모두 PASS)**
- **O1:** 기존 접촉 52,493건을 압축 형식으로 재생해 비교했습니다. float32 왕복이 정확히 일치했고, 충돌·외피 판정이 100% 같았습니다. 경고 389,343건은 바퀴 접촉점 수와 같았습니다.
- **O3:** 그래프에 일부러 17가지 변경을 넣는 시험을 했습니다. 값 변경, 연결 추가·삭제, 노드 추가·삭제·비활성화, 관계 대상 변경, Sdf ChangeBlock 편집, 세션 레이어 편집, 노드 타입 변경, 그래프가 아닌 prim 편집입니다. 모든 경우에 변경 감지 결과와 전체 순회 결과가 같았고, 차단 여부도 같았습니다.
  - 기존 잠금 코드에서 이미 쓰는 ActorCache와 같은 방식(USD 변경 알림)입니다.
  - 실제 실행 중에는 단계가 바뀔 때마다, 그리고 60스텝마다 전체 순회로 대조합니다. 불일치하면 즉시 HOLD합니다.
- **O4:** 실제 forensic 모듈로 1–257건을 기록한 뒤 프로세스를 SIGKILL로 강제종료했습니다. 8개 경우 모두 기록이 100% 남았습니다.
  - write+flush는 매 스텝 그대로 하므로, 프로세스가 비정상 종료해도 기록은 유실되지 않습니다.
  - 유실될 수 있는 경우는 OS 자체가 멈추거나 정전이 날 때뿐이며, 그때도 최대 15스텝(0.25초) 분량입니다.
  - 정지 인증, 경로, 결과 파일은 원래대로 원자적 기록과 fsync를 유지합니다.

**같은 조건 반복 결과 (새로 확인된 사실)**
- 5회 모두 주행 궤적과 최종 오차는 사실상 같았습니다.
- 그러나 **검출 conf는 0.27–0.36으로 매번 달랐습니다.** 기준 0.25에 가깝기 때문에, 같은 조건에서도 렌더 노이즈로 검출 여부가 바뀔 수 있습니다.
- 따라서 본실험의 반복은 정확한 중복이 아니라 인식 단계의 확률적 표본입니다.

## 6. 36시간 이내 완료 가능 여부
- **조건부 가능합니다.**
  - E1 정지 진단에서 운영 카메라 검출은 6건 중 3건이었습니다(C100/C20). V3b의 conf도 0.27로 기준에 가까웠습니다.
  - 이로 보아 주행 비율은 50–70%로 예상되며, 그렇다면 약 27–35시간입니다.
  - 다만 C80–C40의 검출률은 아직 모르기 때문에 보장할 수는 없습니다.
- **목표한 30–33시간은 주행 비율 약 60–65% 이하일 때만 맞습니다.**
- **안전 기준을 유지한 채 1회 210–220초는 현재 방법으로는 어렵습니다.** 남은 후보는 아래와 같으며, 모두 검증 전입니다.
  - 접촉 콜백을 numpy로 일괄 처리: 약 2–3 ms 절감 예상
  - 주행 중 렌더 생략(O5): 이번에 제외함
  - 경로 충돌검사(1회 27초) 최적화: 안전 판정 코드라 권장하지 않음
- **"주행 비율이 높으면 36시간을 넘는다"는 위험은 남아 있습니다.** 진행 중 측정한 소요시간으로 예측해 중간에 보고하는 방식을 제안합니다.

3. 연구자가 원하면 v04 Controller와 Watchdog를 직접 종료합니다. 저는 종료하지 않습니다.
4. 연구자가 개정안, manifest, 옵션 잠금을 승인하고 v05 승인 스크립트를 실행한 뒤 v05를 시작합니다.

3. 개정안, manifest, 실행 옵션 잠금 승인과 v05 승인 절차가 필요합니다.

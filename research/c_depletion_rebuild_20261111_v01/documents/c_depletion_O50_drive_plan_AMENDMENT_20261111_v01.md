# O50 별도 물리 주행 추가 — 계획 개정분 (2026-11-11)

기존 C_DEPLETION_REBUILD 지시와 C 전용 공통 HPO 개정분은 유지한다. 이번 문서는 O50 계획만 추가하며 실행 승인이 아니다. PREPARATION_ONLY/HOLD를 유지하고 신규 렌더링·학습·물리 주행은 시작하지 않는다. 기존 실행 코드·잠금·결과는 변경하지 않는다.

## 추가되는 실험과 분모

| 구분 | 조건 | 계획 실행 수 | 역할 |
| --- | --- | --- | --- |
| 기존 본실험 | 10base×5C×O0/O25×3표현 | 300 | 기존 주 분석, 변경 없음 |
| 추가 강건성 | 10base×5C×O50×3표현 | 150 | 별도 심한 가림 평가 |
| 예정 실행 합계 | 본실험+강건성 | 450 | 작업량 합계이며 주 성공률 분모가 아님 |

O50는 표현당50회, C×표현당10회다. 300과150의 manifest·실행 namespace·결과표·실패 원인·분모·통계분석·보고서를 별도로 관리한다. 450을 단순 합산한 성공률을 주 결과로 사용하지 않는다. 기술 파일럿은 두 본평가 분모에 포함하지 않는다. 과거 L/M50/O50 실행은 새 C O50의 결과로 재사용하거나 합산하지 않는다.

## 대응 설계와 관측 검증

가능하면 계획된 같은10개 base scenario의 Scene 계보·제거 경로·잔여 Bundle ID·시작 위치·카메라·조명·환경·모델 SHA를 공유하고 O50 가림 조건만 변경한다. 실제 새10개 base manifest와150개 실행 ID는 아직 생성하지 않았다. 대응이 불가능한 조건은 차이를 기록하고 동일조건의 paired 비교로 주장하지 않는다. 동일base의 C/표현/가림은 관련 표본이며150개의 독립환경으로 세지 않는다.

새 O50마다 aligned RGB·Depth·target/all-instance GT·panel mask·calibration·실제 가림률을 독립 검증한다. 다른 O조건이나 fixture의 측정값을 복사해 현재 프레임 실측으로 보고하지 않는다. 기존 잠긴 가림률·visibility·정합 QA 임계값을 완화하지 않는다. 원래 panel 저장 시점 문제를 방지하고 실제 capture 시점의 mask를 저장해야 한다. GT는 fixture/QA/evaluation 역할에만 두고 target 선택·pose·controller 입력에 넣지 않는다. 기존 규칙대로 촬영 후 가림판을 제거하고 이동 전 확인하는 계약도 유지한다.

## 단계별 진입 조건과 실행 순서

기존 C 데이터 생성/QA/split lock → C 전용 공통 HPO → 최종 모델 고정/학습 seed 반복 → C 인식 및 RGB-D 위치추정/ROBUST_A 평가를 먼저 수행한다. 이어 별도 O50 기술 파일럿을 수행해5C 및세표현의 안전성과 실행 가능성·로그/영상/GT 저장·정지/정숙/정리 계약을 검증한다. 파일럿의 구체 membership와 판정은 실행 전에 별도 잠금하며 이번에 생성하지 않는다.

O50 추가 본평가는 **모든 기존 gate + O50 인식/pose 평가 완료 + O50 GT/가림 QA PASS + 별도 O50 기술 파일럿의 안전/실행 gate PASS + 150회 manifest/버전/모델 SHA 잠금 + 신규 실행 승인**이 있어야 진입한다. 인식 성공률이 낮다는 이유로 실패 조건을 제거하거나 성공 가능한 조건만 선정하지 않는다. 기술적 관측·기록이 유효한 인식 실패와 환경/안전 이상을 구분한다. 안전 이상·로봇 상태 불명·GT 불일치·규칙 충돌은 HOLD다.

기본 계획 순서는 기존 기술 파일럿 → 본실험300회 → O50 기술 파일럿 → 별도O50 150회다. 공통 C 인식/pose 평가의 O50 부분은 그 전에 완료해야 한다. 이 순서는 현재 실행을 시작하거나 본실험300회의 선행 gate를 해제하지 않는다.

운용은 본실험과 같은 G1 ROBUST_A 단일 관측이며 중간 재인식은 사용하지 않는다. C 호환 수정이 필요하면 기존 지시에 따른 별도 version과 사전 검증을 적용하고 O50 성능을 보고 파라미터를 재튜닝하지 않는다. 기존 ROBUST_A·로봇/경로제어·충돌/속도/조향/정지·성공 판정 조건을 임의 완화하지 않는다. 현재 단일 작업 성공 기준 미확정 HOLD도 그대로 적용된다.

## 실패·분모·통계

각 선언 시행은 인식 무검출/검출 실패, 다른 적재물·가림판·배경 오선택, pose 계산/지정목표 pose 실패, 경로 거절, 안전 정지, 실제 이동, PRE/FINAL 정지 인증, quiet·충돌, 최종 위치/yaw 오차와 작업 성공을 단계별로 기록한다. 메모리/TF/촬영·인프라 오류와 원문 로그도 보존한다. 같은 시행에서 여러 후속 단계가 미실행이면 최초 실패와 NOT_RUN을 구분하고 중복 실패 건수로 분모를 늘리지 않는다.

실패·중단을 제외하거나 성공할 때까지 재시도하지 않는다. 선언150·실제시도·완료·성공·실패·중단·HOLD·미실행을 각각 제시한다. 미실행을 성공/실패/완료로 임의 처리하지 않으며150회가 닫히기 전 최종 완결 결과로 표시하지 않는다. 통상 실패 다음에는 사전 선언 순서를 따르고, 안전/환경 문제가 남으면 다음 주행도 HOLD다.

O50 작업 성공률과 Wilson 기술구간, 표현 간 같은base의 대응 비교, O0/O25 대비 matched O50 성능 저하를 별도 보조 분석한다. 반복측정·base cluster를 고려하고 주300회 성공률과 합치지 않는다. 비열등성10%p는 이번에도 확정하지 않는다. O50 Test/주행 결과로 HPO 후보·checkpoint·성공 기준을 재선정하지 않는다.

## 자원과 남은 범위

추가150회의 물리 작업은 과거 G1 성공 평균479.04초/회로 약19.96시간, 보수적9분/회로22.5시간이다. 450회의 물리 작업만 약59.88–67.5시간이며 새 C-HPO·데이터·QA·평가·두 기술파일럿 시간은 별도다. O50의 빠른 출발 전 실패나 추가 소요로 실제 처리속도가 달라질 수 있으므로 실측 전 확정 ETA가 아니다. 48시간은 강제 종료/분모 축소 조건이 아니다.
